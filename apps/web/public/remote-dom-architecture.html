Architecture Specification

Omni Remote DOM & IPC Lifecycle

Complete technical guide to sandboxed guest mutation streaming and bidirectional event propagation.

1. High-Level Architecture Overview

Omni runs third-party and core plugins inside sandboxed iframes. Unlike typical iframes that render UI within their own viewport, Omni uses Shopify's Remote DOM architecture to project virtual elements from the sandboxed iframe directly into the host shell's native layout slots (dock, main, sidebar, header-status, header-actions).

🛡️ Sandbox Guest (Iframe)

Runs untrusted plugin logic. Has access to window.omni bridge and lightweight RemoteElement tree.

1 Plugin registers component via omni.registerComponent()
2 Creates detached elements: root.createElement("button")
3 Attaches event listener: btn.addEventListener("click", fn)
4 Appends to root: root.appendChild(card)
⚡ Host Kernel (Native DOM)

Controls layout slots, access control governance, and native rendering via DOMRemoteReceiver.

5 RemoteDomHost intercepts mutations and wraps event listeners
6 DOMRemoteReceiver creates native HTML element on host DOM
7 User clicks native button in host window
8 Host callback forwards event ID to sandbox over MessagePort
⇄ MessagePort (Channel 1: Fast Remote DOM stream) & MessagePort (Channel 2: JSON-RPC 2.0 Kernel) ⇄

2. Dual-Channel IPC Isolation

When OmniKernel mounts a plugin in SandboxInstance, it creates two distinct MessageChannel pairs transferred via postMessage during handshake:

  • Channel 1 (portRemoteDom): High-speed mutation stream. Responsible exclusively for Remote DOM mutations (type "mutate") and host event routing (type "event").
  • Channel 2 (portRpc): Capability-governed JSON-RPC 2.0 bus. Used for asynchronous kernel operations: nostr.subscribe, nostr.publish, storage.get/set, ui.toggleSlot, and profile.*.

3. The Mutation Protocol (Guest → Host)

As elements are created, modified, or deleted in the sandbox, the guest runtime queues mutation tuples and flushes them on a microtask (queueMicrotask). 

// Mutation Record Shapes:
[0, parentId, serializedChildNode, index]   // MUTATION_TYPE_INSERT_CHILD
[1, parentId, childIndex]                   // MUTATION_TYPE_REMOVE_CHILD
[2, textNodeId, newTextContent]             // MUTATION_TYPE_UPDATE_TEXT
[3, elementId, propertyName, value, type]   // MUTATION_TYPE_UPDATE_PROPERTY
                                            // type 1 = Property, 2 = Attribute, 3 = EventListener

Why Function References Cannot Cross postMessage

In JavaScript, functions cannot be cloned or transferred across postMessage. When a guest element calls btn.addEventListener("click", callback), the sandbox records callback in its local eventListeners Map and serializes the listener declaration simply as { click: true } or sends mutation [3, btnId, "click", true, 3].

The Host Wrapping Solution:
Shopify's DOMRemoteReceiver requires that event listeners passed to it be callable functions. In RemoteDomHost.mutate(), the host recursively traverses newly inserted trees (mutation 0) and property records (mutation 3). It replaces true with a host-side callback: 
node.eventListeners[eventName] = (detail) => {
  this.onEvent(this.componentId, { id: node.id, eventName, detail });
};

4. Event Dispatch & Bubbling (Host → Guest)

When the user clicks a projected element in the host DOM:

  1. The browser dispatches a native DOM event on the target element.
  2. DOMRemoteReceiver's listener triggers and executes our wrapped callback.
  3. The host fires onEvent(), sending { type: "event", componentId, id: "btn-start", eventName: "click" } over Channel 1 to the sandbox.
  4. In omni-runtime.js, handleHostEvent() looks up the element by ID and invokes the guest listener functions registered for that event name.

Hit-Testing & Strict Target Checks

Shopify's DOMRemoteReceiver includes an intentional security and isolation check: 

if (event.target !== element) return;

If a button contains child elements (e.g. <button><svg><circle/></svg> <span>Start</span></button>), clicking on the label or icon causes the browser to report event.target as the <span> or <circle>, not the <button>.

Resolution:
In style.css, button descendants receive: 
.omni-slot button *, .dock-item * {
  pointer-events: none;
}
This causes the browser's hit-testing to treat the parent <button> as the direct event target, guaranteeing that event.target === element always matches and triggers cleanly.

5. Reactive Updates (Sandbox → Host)

When a plugin's click handler runs (e.g. Pomodoro timer ticking down, or checklist item toggling):

  1. The plugin mutates state: remainingSeconds-- and sets timeText.textContent = "24:59".
  2. In omni-runtime.js, RemoteElement.textContent checks if a single text child already exists. If so, it calls this.childNodes[0].data = "24:59".
  3. RemoteText.data immediately emits mutation [2, textId, "24:59"].
  4. queueMicrotask flushes the mutation across Channel 1 within the same browser turn.
  5. On the host, DOMRemoteReceiver.updateText() updates the native DOM text node in place: textNode.data = newText with zero element teardown or reflow overhead.
